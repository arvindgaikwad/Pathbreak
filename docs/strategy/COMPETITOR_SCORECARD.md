# Pathbreak — Competitor Scorecard

Last updated: 2026-08-06

## Purpose

This scorecard converts competitor research into product decisions. It is not intended to declare a winner from incomplete public data. Public store install bands, ratings, reviews, screenshots, descriptions, and visible monetization are treated as market signals only.

## Scoring method

Each product is scored from 1 to 5 on the dimensions visible from public listings and product review patterns.

- 1 = weak or absent
- 3 = acceptable category standard
- 5 = category-leading or highly differentiated

The scores are directional and must be reviewed quarterly.

## Pathbreak gap analysis

### Current advantages

- Nearest-path touch selection is designed to avoid wrong-path penalties.
- Empty and ambiguous taps can be ignored rather than punished.
- High contrast, reduced motion, and haptic controls are planned early.
- Monetization is intentionally restrained.
- Offline-first architecture avoids account and network friction.

### Current disadvantages

- Only a small number of levels exist.
- The visual identity is still temporary.
- There is no daily puzzle, chapter mechanic, or content cadence.
- The app has no store history, ratings, reviews, or brand awareness.
- The level editor, solver, analytics, ads, and purchase systems are unfinished.

## Competitive feature matrix

| Feature | Category standard | Pathbreak decision |
|---|---|---|
| Directional paths | Required | Keep as the base rule |
| Lives after blocked taps | Common | Challenge Mode only |
| Relax/no-timer messaging | Common | Make Relax Mode genuinely pressure-free |
| Hint highlights a valid move | Common | Keep, but make touch feedback clearer |
| Hundreds of levels | Common claim | Prioritize 75 reviewed levels over inflated volume |
| Daily challenge | Strong products | Add only after progression is stable |
| 3D rotation | Some adjacent products | Exclude from version 1 |
| Interstitial ads | Common | Cap and delay until after Level 10 |

| Accessibility controls | Inconsistent | Make this a product pillar |
| Solver-verified content | Rarely visible | Use internally as a quality moat |
| Ambiguous-tap protection | Rarely marketed | Make this a store-listing promise |

## White-space opportunities

### 1. Precision promise

Store message:

> Precise controls. No accidental penalties.

Required proof:

- larger invisible hit areas;
- nearest-path selection;
- ambiguous tap detection;
- small-screen testing;
- analytics event for ignored ambiguous taps.

### 2. Two player moods

- Relax Mode for calm completion without lives.
- Challenge Mode for mistakes, stars, and personal bests.

This provides broader audience coverage without making the default experience stressful.

### 3. Readable difficulty

Pathbreak should avoid difficulty created only by visual clutter. Difficulty should come from sequencing, branching, and original mechanics while maintaining legibility.

### 4. Respectful monetization

The player should never believe the puzzle was made frustrating to force an ad or purchase.

### 5. Original chapter mechanics

A new mechanic every 10–15 levels creates a stronger identity than merely increasing board density.

## Competitive response rules

When a competitor launches a feature, do not copy it automatically. Evaluate:

1. Does it solve a proven Pathbreak player problem?
2. Does analytics show a need?
3. Does it support Fair, Readable, Calm, Fresh, or Respectful?
4. Can it be built and maintained without damaging the content pipeline?
5. Can it be expressed in an original way?

## Quarterly review checklist

- Refresh install bands, ratings, and review counts.
- Read the newest 50 useful competitor reviews.
- Record new monetization placements.
- Capture new store screenshots and feature claims.
- Note repeated complaints and praise.
- Compare Pathbreak retention, crash, rating, and revenue performance.
- Update the scorecard only when evidence changes.
